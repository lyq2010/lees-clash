# 轻量 Smart

默认遵循配置。YAML 的 `proxy-groups` 支持 `type: smart`。应用内仅允许将原配置中的 `url-test` 组转换为轻量 Smart：节点页提供带文字和滑动开关的独立控件，工具页提供当前配置所有 URLTest 组的批量开关与已启用数量。选择、故障转移、负载均衡及 YAML 原生 Smart 等其他组不显示转换入口，也不能通过接口强制转换。

覆盖按配置文件和策略组名称保存于独立的 `smart.json`，不修改订阅 YAML；订阅更新保留该文件，但同名组已变为非 URLTest 时忽略旧覆盖。工具批量操作为一次保存、一次重载，开启前校验所有目标组，不会留下部分启用结果；关闭恢复所有当前 URLTest 组遵循配置。单组可独立关闭，工具页显示部分启用数量；新增 URLTest 组由下次批量操作覆盖。已有 YAML 原生 Smart 不受这些开关影响。现有普通选择组与手动节点选择保留。

```yaml
proxy-groups:
  - name: 自动选择
    type: smart
    proxies: [节点A, 节点B]
    url: https://www.gstatic.com/generate_204
    interval: 300
    timeout: 3000
```

支持现有 `use`、节点筛选、排除、图标与 `disable-udp`。仅实际代理节点参与选路，嵌套策略组和内置 DIRECT / REJECT 等不参与；没有可用节点时失败，不隐式直连。

## 选路与故障处理

当前是基于规则和统计反馈的自适应选路，没有机器学习模型。它与 `url-test` 的区别是：测速网址只是一种参考，实际连接的首包、失败和站点历史也会改变新连接的选择；不同站点可以同时走不同节点。

- 真实 TCP 首次响应和 UDP 首次回应更新衰减平均延迟；URL 测试提供独立健康状态和冷启动参考，不清除真实业务失败的退避。TCP / UDP 分别记录质量。
- 优先保持同一站点近期成功的线路，明显落后于更好候选时换线；最近失败的站点 / 节点组合降权。站点键使用注册域或目标 IP，单键最多253字节。
- 拨号阶段最多尝试三个不同候选，每次受 `timeout` 与调用方取消约束；连续失败进入最长64秒的退避。
- 首次发送后等待 TCP / UDP 首个响应的时间受 `timeout` 限制。无响应时当前连接失败并降权，后续连接使用其他候选；不自动重放已发送的业务数据。收到首个响应后恢复调用方原超时，不限制正常长连接。
- `now` 显示最近实际拨号成功的节点，新连接可能根据目标站点选择其他节点。

### 评分与稳定性细节

节点评分按策略组、节点、TCP / UDP 分开保存。有效 URL 测速延迟是基础值，未测试时用500ms作初始参考，已有失败健康状态时使用10000ms参考值，避免失败节点排在健康但较慢的节点之前。首次真实成功样本直接作为平均值；后续成功样本的权重为 `max(0.2, 1-exp(-距上次更新秒数/300))`，样本延迟最高计10000ms。长时间不用的旧平均值在选路时按 `exp(-记录年龄秒数/600)` 衰减回测速参考值，避免旧成绩永久占优。

失败计数最多6次，参与评分的惩罚为每次500ms并随年龄衰减；退避期间额外加大惩罚。退避时长依次为2、4、8、16、32、64秒，真实成功样本清除退避与失败计数。每站点仍只保存一个成功节点、一个降权节点，并在原记录空间内保存成功耗时与时间。成功节点在本站点的近期耗时为评分下限，随600秒时间常量衰减，避免其他网站的快速样本掩盖本站点的慢响应。

10分钟内的新鲜站点记录仅在替代线路耗时不超过原线路的 `1.25倍+50ms` 时更新；更快替代线路成功后，原明显较慢线路暂时降权，避免立即跳回。较慢的迟到成功保留原快速线路；实际失败或明显较慢的线路复用同一个降权槽，生效10分钟。站点记忆总期限仍为1小时，不建立节点与站点的矩阵。首响应包含服务端处理时间，不能据此判断内容解锁或网络带宽。

同站点最近成功节点的得分只要不超过“最佳得分 × 1.25 + 50ms”，就继续优先使用；否则切换到更好候选。得分中还加入0～24ms的稳定站点哈希偏移，用于在接近的节点之间分散不同站点，不做每次请求随机换线。排名只保留三个候选，不分配全组排序数组。

站点键优先采用注册域（例如 `a.example.com` 与 `b.example.com` 归为 `example.com`），没有域名时采用目标 IP；它不记录 URL 路径、查询参数或响应正文。运行时统计使用有界内存缓存，并在当前配置的私有目录保存学习快照，重载及重启时恢复尚未过期的结果，不写入订阅。

### 当前能力边界

- 每条真实连接可以正常并发；“全局2个工作者”限制的是主动探测，不是把用户流量限制为两条连接。
- 当前不测吞吐带宽、不做 TCP 重传率评分，不检测流媒体解锁或内容地区限制；成功收到响应不等于目标内容已解锁。
- Smart 不迁移已建立连接。拨号失败可以在当前拨号过程中换候选；数据已经发出后出现首包超时，当前连接会失败，由后续新连接换线，不重放请求。
- UDP 在首次发送后等待首次回应；单向、正常就不返回数据的 UDP 业务不适合用“有无首回应”判断质量，应使用合适的普通组或超时设置。
- 没有实现 Smart 组内临时固定节点。应用内“遵循配置”会恢复当前 YAML 的组类型，而不是将所有组统一改成手动组。
- 只含嵌套策略组的入口不能直接覆盖为 Smart；应在包含实际节点的下级组启用，或让 YAML Smart 组直接使用节点 / `use` 提供器。没有实际节点时应用会提示，不会隐式直连。

## 内存与后台预算

- 所有组共享最多4096条节点统计、1024条站点记忆，不建立“节点数 × 站点数”矩阵，不记录完整请求或连接历史。快照保留这些有期限的站点键，存储及清理规则见下节。
- 节点统计30分钟、站点记忆1小时过期；在访问和容量淘汰时清理，不运行空闲清理定时器。
- Smart 自身无常驻定时任务；有流量时按 `interval` 触发轮转探测，每轮最多4个节点，全局最多2个探测工作者。自动轮次跳过在该间隔内已有真实成功样本的节点，优先补充未知、失败或陈旧的观测；不增加请求预算。手动测速仍覆盖全组并共享并发预算，应用入口总时限2分钟；配置重载立即取消进行中的手动探测。HTTP 状态不符合 `expected-status` 也会判为探测失败。
- 默认 `interval: 300` 秒，范围60～86400秒；默认 `timeout: 3000` 毫秒，范围500～10000毫秒。外部资源自己声明的健康检查继续遵循配置，Smart 不额外向它注册定时检查。
- 不加载模型、不采集训练数据、不新增 ASN 库或数据库。配置替换时取消旧探测并清理该组统计。
- 原生复制路径在取得首包后恢复上游优化，避免全程按包统计和额外复制。内存页诊断仅暴露统计数量与预算，不暴露站点或节点名称。

## 学习结果持久化与清理

- 每份配置的 `smart-state.jsonl` 最多2MiB，与开关设置 `smart.json` 分开。节点评分、失败退避、站点优选及耗时按组名恢复到新内核对象；保留原来的节点30分钟／站点1小时过期时刻，不因重启延长。配置正文的SHA-256变化时不恢复旧快照，也过滤已经不存在的节点。
- 仅在有新样本且达到5分钟间隔时启动一次短期写入任务；没有定时器或空闲唤醒。正常停止和重载会补存尚未写入的变化。异常强杀可能丢失上次快照后的变化，缓存不是每条样本同步落盘。
- 文件以0600权限写入临时文件并原子替换。临时文件也受2MiB上限限制；正常结束会清理临时文件。损坏、超限、不兼容及过期快照不会阻止启动，不触发外网恢复。
- 写入只复制最多4096＋1024个键，约160KiB，逐条编码；恢复先流式校验再流式应用，没有整文件缓冲、常驻快照副本或额外统计容量。恢复复用当前节点名称，避免保留解码得到的重复节点字符串。
- 工具页Smart区域提供“清除学习记录”，确认后清除当前配置的内存学习和磁盘快照；保留开关设置，后续真实连接继续学习。取消确认不清理文件，旧的待写入任务不会重新写回被清除的旧记录。

这属于本项目独立增加的恢复能力；Surge 6.10.0已追踪的初始化／策略重建路径是内存学习；分析临时产物已按授权移入废纸篓。

参考 [Surge Smart 的公开行为](https://manual.nssurge.com/policy-groups/smart.html)设计独立实现；本机6.10.0的静态分析仅作行为参考，临时分析报告与反编译产物已按授权移入废纸篓。未复制其代码、全量候选数组或固定5分钟定时测试，也不兼容 vernesong 的机器学习扩展参数。未实现 Surge 的 TCP 重传率评分。
